📌 Antes de escribir código:
- Piensa paso a paso.
- Planifica antes de actuar.
- Divide el trabajo en tareas pequeñas y claras.

📂 Estructura de carpetas recomendada:
- `pages/`: vistas y rutas.
- `components/`: componentes visuales reutilizables.
- `hooks/`: lógica en React hooks.
- `lib/`: utilidades generales y lógica de negocio.
- `types/`: definiciones globales TypeScript.
- `api/`: conexión a servicios externos.
- `__tests__/`: pruebas unitarias organizadas por módulo.
- `sandbox/`: zona exclusiva para pruebas, ideas, mockups, borradores.
  - `sandbox/components/`, `sandbox/scripts/`, `sandbox/test-data/`, `sandbox/playground/`.

📏 Buenas prácticas de código:
- Máximo 300 líneas por archivo.
- Máximo 80 líneas por función.
- Componentes con más de 200 líneas deben dividirse.
- Nombres claros y consistentes (`camelCase`, `PascalCase`, `snake_case` según contexto).
- Usa `eslint` y `prettier` para mantener formato.

🔁 Flujo de pruebas y reinicios:
- Si hay cambios que requieren reiniciar `npm`, hazlo automáticamente.
- Usa `curl` para probar endpoints si es útil.

✅ Tareas:
- Nunca borres tareas hechas. Se marcan como completadas, se mejora o se agregan nuevas.
